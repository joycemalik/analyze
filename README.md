# Sales Analytics Pipeline and Dashboard

This project demonstrates a simple data analytics pipeline that processes sales data, computes key metrics, and displays them on a minimalist web dashboard. The pipeline is automated using GitHub Actions, which generates a JSON report and publishes it via GitHub Pages.

## Project Structure

-   `.github/workflows/ci.yml`: Defines the GitHub Actions workflow for continuous integration and deployment.
-   `execute.py`: A Python script that reads `data.xlsx`, performs calculations (total rows, distinct regions, top products by revenue, 7-day rolling revenue per region), and outputs the results as JSON.
-   `data.xlsx`: The raw sales data (must be committed to the repository).
-   `data.csv`: A CSV version of `data.xlsx`. This file should be generated from `data.xlsx` (e.g., using `pandas.read_excel('data.xlsx').to_csv('data.csv', index=False)`) and committed to the repository. It is not directly used by `execute.py` but is part of the committed artifacts.
-   `index.html`: A single-file HTML application that fetches `result.json` from GitHub Pages and displays the analytics dashboard.
-   `result.json`: The analytics report generated by `execute.py` in the CI pipeline. **This file is not committed to the repository; it's generated and published via GitHub Pages.**

## How to Use

### Setup (Local Development)

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/your-username/your-repo-name.git
    cd your-repo-name
    ```
2.  **Ensure `data.xlsx` is present:**
    The `execute.py` script expects `data.xlsx` to be in the root directory. This file should be committed to the repository. A `data.csv` file, converted from `data.xlsx`, should also be committed.
3.  **Set up Python environment:**
    Install Python 3.11+ and the required packages:
    ```bash
    python -m venv .venv
    source .venv/bin/activate # On Windows: .venv\Scripts\activate
    pip install pandas==2.3 openpyxl ruff==0.5.0
    ```
4.  **Run the analytics script locally:**
    ```bash
    python execute.py > result.json
    ```
    This will generate `result.json` in your local directory.
5.  **View the dashboard locally:**
    Open `index.html` in your web browser. It will attempt to load the local `result.json` file.

### CI/CD (GitHub Pages Deployment)

1.  **Push your changes to GitHub:**
    Ensure `execute.py`, `data.xlsx`, `data.csv`, `index.html`, and the `.github/workflows/ci.yml` file are pushed to the `main` branch of your GitHub repository.
2.  **GitHub Actions Workflow:**
    The `ci.yml` workflow will automatically trigger on `push` to `main`.
    -   It sets up a Python 3.11 environment.
    -   Installs `pandas==2.3`, `openpyxl` (for `.xlsx` reading), and `ruff==0.5.0` (for linting).
    -   Runs `ruff check .` for code style and quality checks.
    -   Executes `python execute.py > result.json` to generate the analytics report.
    -   Publishes `result.json` as a GitHub Pages artifact.
    -   Deploys `result.json` to GitHub Pages.
3.  **Access the Live Dashboard:**
    Once the GitHub Actions workflow completes successfully (specifically the "deploy-pages" job), your dashboard will be available via GitHub Pages. The URL will typically be `https://<your-username>.github.io/<your-repository-name>/`. The `index.html` file will fetch `result.json` from `https://<your-username>.github.io/<your-repository-name>/result.json`.

    You might need to enable GitHub Pages in your repository settings (Go to your repository -> Settings -> Pages -> Build and deployment -> Source: GitHub Actions).

## Code Explanation

### `execute.py`
This Python script uses the `pandas` library to perform data analysis:
-   Reads `data.xlsx`.
-   Calculates `revenue` (`units * price`).
-   Computes the total number of rows (`row_count`).
-   Counts distinct regions (`regions`).
-   Identifies the top 3 products by total revenue (`top_n_products_by_revenue`).
-   Calculates the last value of a 7-day rolling average of daily revenue for each region (`rolling_7d_revenue_by_region`).
-   The output is a JSON string printed to standard output, containing these aggregated metrics.
-   **Fix Applied:** A non-trivial error was fixed by correcting a typo from `"revenew"` to `"revenue"` in the daily revenue calculation, ensuring accurate data aggregation.

### `index.html`
This is a minimalist, single-file HTML application designed for simplicity and efficiency:
-   It includes inline CSS for basic, clean styling.
-   On page load, it uses vanilla JavaScript (`fetch` API) to asynchronously retrieve the `result.json` file from the same origin.
-   It parses the JSON data and dynamically renders the analytics results (total rows, distinct regions, top products, rolling revenue) into a user-friendly HTML structure.
-   Basic error handling is included to display a message if the data cannot be loaded, guiding the user on potential issues.

### `.github/workflows/ci.yml`
This GitHub Actions workflow automates the data processing and deployment:
-   **Trigger**: Runs automatically on `push` events to the `main` branch and can also be manually triggered (`workflow_dispatch`).
-   **Environment**: Executes on an `ubuntu-latest` runner and sets up Python 3.11.
-   **Dependencies**: Installs `pandas==2.3`, `openpyxl` (necessary for `pandas` to read `.xlsx` files), and `ruff==0.5.0` (a fast Python linter).
-   **Linting**: Runs `ruff check .` to ensure code quality and adherence to style guidelines.
-   **Data Processing**: Executes `python execute.py` and redirects its standard output to `result.json`, creating the analytics report.
-   **GitHub Pages Deployment**:
    -   It first prepares `result.json` by moving it into a `_site` directory, which is a common convention for static site deployments.
    -   Uses `actions/upload-pages-artifact@v3` to upload the `_site` directory as a GitHub Pages artifact.
    -   Uses `actions/deploy-pages@v4` to deploy this artifact to GitHub Pages, making `result.json` accessible at the root of the Pages site (e.g., `https://<username>.github.io/<repo-name>/result.json`). This ensures the `index.html` can fetch the report.
